# 发型体系升级设计文档

> 日期：2026-07-26
> 状态：待评审
> 方案：方案 B — 结构化发型体系

## 1. 背景与目标

### 1.1 现状

当前 Image2 人像 Skills 的发型相关能力评分约 5/10，存在以下短板：

- 核心发型知识库（`hairstyle-reference.md`）仅 12 种发型，且以长发为主，短发、编发、特殊造型覆盖不足
- 缺少结构化维度拆解（长度/卷度/刘海/发色/发质/造型手法各成体系）
- 发色仅覆盖黑/棕/金三大系，缺少流行色、挑染、渐变等
- 刘海类型不完整，缺少空气刘海、齐刘海、胎毛刘海、眉上刘海等
- 发质/发量维度完全缺失
- 参考词表.md 无发型专章
- 3 个 Skill（portrait-director / wedding-portrait / sports-venue-portrait）完全没有发型逻辑
- 缺少发型 × 脸型搭配知识
- portrait-prompt-crafter 中只有 5 种简易发型描述

### 1.2 目标

将发型能力从"零散描述"升级为"结构化可组合系统"，实现：

- 25+ 种完整发型预设，覆盖基础剪发/扎发盘发/编发/刘海纹理/风格化发型
- 6 维结构化词库（长度/卷度/刘海/发色/发质/造型手法），支持自由组合
- 11 个 Skill 全部接入发型体系（从 8/11 → 11/11）
- 发型 × 脸型搭配指南
- 参考词表新增发型专章
- risk-debugger 新增发型专项修复策略

### 1.3 非目标

- 不新增独立 Skill（图鉴类 Skill 另行评估）
- 不改变各 Skill 的输出格式和调用方式
- 不增加男性发型专题（当前 Skill 以女性人像为主，男性需求通过中性维度组合处理）
- 不修改任何现有安全边界

## 2. 整体架构

发型体系采用三层结构：

```
┌─────────────────────────────────────────┐
│  各 Skill 层（11 个）                    │
│  按自身定位调用发型能力                  │
├─────────────────────────────────────────┤
│  发型服务层                              │
│  pick-hairstyle / compose-hairstyle /   │
│  hairstyle-negative-prompts             │
├─────────────────────────────────────────┤
│  知识库层                                │
│  6 维词库 + 25+ 预设 + 脸型搭配指南      │
└─────────────────────────────────────────┘
```

核心原则：各 Skill 不各自维护发型知识，统一从共享库调用，保证一致性和可维护性。

## 3. 核心组件

### 3.1 结构化发型知识库

**文件位置**：`skills/_shared/knowledge/hairstyles.md`

现有 `skills/_shared/references/hairstyle-reference.md` 保留作为兼容别名，内容改为引用新知识库的一句话重定向。原有 8 个直接引用该文件的 Skill 逐步迁移到 `knowledge/hairstyles.md`。

包含两大部分：

| 刘海 | 10 | 无刘海露额 / 中分 / 侧分 / 八字刘海 / 法式刘海 / 空气刘海 / 齐刘海 / 眉上刘海 / 胎毛刘海 / 公主切 |
| 发色 | 13 | 自然黑 / 黑茶色 / 深棕色 / 栗棕色 / 蜜茶棕 / 亚麻金 / 白金 / 酒红 / 灰蓝 / 粉棕 / 挑染 / 渐变 balayage / 挂耳染 |

#### 3.1.2 25+ 种完整发型预设

每种预设包含：
- 中文名 / 英文名
- 基础维度（长度 / 卷度 / 刘海 / 推荐发色 / 发质 / 造型）
- 详细中文描述（15-30 字，可直接用于 prompt）
- 适配气质与风格
- 适合脸型

预设分类：

| 分类 | 数量 | 代表发型 |
|---|---|---|
| 基础剪发 | 5 | 直长发 / Bob / Lob / Pixie 精灵短发 / 公主切 |
| 扎发盘发 | 5 | 高马尾 / 低马尾 / 半扎发 / 丸子头 / 低盘发 |
| 编发系列 | 5 | 三股麻花辫 / 鱼骨辫 / 法式编发 / 荷兰编发 / 花环编发 |
| 刘海与纹理 | 5 | 八字刘海 / 齐刘海 / 侧分刘海 / 海浪卷 / 温柔大卷 |
| 风格化发型 | 5+ | 港风侧分大卷 / 法式慵懒卷 / 湿发造型 / 狼尾层次剪 / 锁骨内扣 |

### 3.2 发型 × 脸型搭配指南

**文件位置**：`skills/_shared/references/face-shape-hairstyle-guide.md`

6 种脸型 × 推荐发型 & 避雷发型：

| 脸型 | 推荐发型方向 | 避雷 |
|---|---|---|
| 鹅蛋脸 | 几乎所有发型 | — |
| 圆形脸 | 头顶蓬松、侧分、长款层次 | 齐刘海、贴头皮直发 |
| 方形脸 | 柔和卷度、八字刘海、侧分 | 利落短发、齐耳 Bob |
| 长形脸 | 横向蓬松、齐刘海、侧分卷发 | 贴头皮长直、高马尾 |
| 心形脸 | 侧分、下颚蓬松、波波头 | 露额高马尾、超短发 |
| 菱形脸 | 侧分刘海、中长卷发、蓬松感 | 贴头皮、中分长直 |

供 portrait-director（推荐时）和 risk-debugger（修复时）调用。

### 3.3 参考词表新增发型专章

**文件**：`参考词表.md`

新增章节："十一、发型速查表"，包含：
- 按风格路线推荐发型（与现有 24 种风格路线一一对应）
- 按长度快速选型（短/中/长各 5 款代表）
- 发色与气质对照表

### 3.4 发型负面提示词集

集成到各 Skill 的负面提示词中，新增：
- 假发感、发型不对称、刘海变形、发色不均
- 编发结构错误、发量异常、发际线不自然
- 头发融合背景、发丝粘连

## 4. Skill 接入方案

### 4.1 统一调用方式

各 Skill 按照以下 3 种标准模式调用发型能力（在 Skill 流程中以内联规则+知识库引用的形式实现，不是独立代码函数）：

1. **按风格选款（pick-hairstyle）** — 从预设池中根据风格标签和脸型筛选，返回 1 款完整发型描述
2. **按维度组合（compose-hairstyle）** — 根据用户提供的 6 维关键词，从词库中拼装成完整描述
3. **负面提示词（hairstyle-negative-prompts）** — 返回发型相关的负面提示词清单

### 4.2 各 Skill 接入详情

| Skill | 改动内容 | 默认发型策略（用户未提时） |
|---|---|---|
| `portrait-director` | 新增发型路由逻辑，根据风格/脸型推荐发型 | 按选定风格路线推荐 1 款 |
| `structured-portrait-prompt` | "发型方向"字段升级，支持预设名 + 维度组合 | 随机选 1 款，可选变化参数列 3 款替换 |
| `portrait-prompt-crafter` | 发型维度词库替换为 6 维 + 25+ 预设 | 随机选 1 款，可替换 |
| `adult-glamour-studio` | 扩充发型引用，增加魅力向子集 | 从魅力子集随机（大波浪/低盘发/湿发/长直） |
| `wedding-portrait` | 从通用预设池中标记新娘向子集（低盘发/公主头/半披发/编发盘发等 8+ 款），新增婚纱-发型匹配逻辑 | 按婚纱版型推荐：拖尾→低盘发，轻纱→半披发，中式→盘发配簪 |
| `fashion-lingerie-lookbook` | 从通用预设池中标记内衣/泳装适配子集 | 从适配子集随机（大卷/低马尾/湿发） |
| `sports-venue-portrait` | 从通用预设池中标记运动向子集（高马尾/拳击辫/丸子头/发带造型等） | 从运动子集随机 |
| `character-poster-cover` | 增加海报感发型推荐 | 按海报风格推荐 |
| `character-reference-sheet` | 扩充预设池，保持一致性 | 随机选 1 款锁定 |
| `aesthetic-rewriter` | 增加发型改写策略 | 保留原发型，低俗时替换为成熟版本 |
| `risk-debugger` | 新增发型专项诊断与修复 | — |

### 4.3 数据流转

```
用户输入
  │
  ├─ 明确指定具体发型 ─→ 命中预设 → 用户维度覆盖预设值 → 生成描述
  ├─ 只给维度关键词 ─→ 6 维词库匹配组合 → 生成描述
  └─ 完全没提发型 ─→ 各 Skill 按默认策略选款 → 生成描述
                            │
                            ▼
                   拼入主 Prompt 发型字段
                            │
                            ▼
                   追加发型负面提示词
```

## 5. 边界情况处理

| 场景 | 处理方式 |
|---|---|
| 用户描述与预设冲突 | 用户维度优先，预设仅作基础模板 |
| 用户要的发型不在预设中 | 从 6 维词库拆解组合，不强行匹配 |
| 多发型描述冲突 | 取最后一个有效描述，或在导演扩展中标注矛盾 |
| 发色与风格不搭 | 保留用户选择，在导演扩展中加风格提示 |
| 男性发型需求 | 从长度/卷度维度中性组合，不加女性化描述 |
| 复杂发型 AI 易画错（编发/盘发） | risk-debugger 预置专项修复策略 |

## 6. 风险控制

1. **不破坏现有行为**：输出格式不变，只提升发型描述质量
2. **默认发型不硬塞**：保留"用户不提不强制"原则
3. **发型描述长度控制**：单款发型描述 15-30 字，不喧宾夺主
4. **安全边界不变**：不放松任何现有安全规则
