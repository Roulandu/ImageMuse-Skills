# Image2 女性人像 Skills 演进设计

## 目标

在保留现有八个垂直场景 skill 专业度的前提下，建立一个可路由、可复用、可诊断的 Image2 人像 prompt 体系；新增高价值题材时不再复制安全、参数和输出规则。

## 范围与非目标

- 范围：共享工作流、总导演入口、现有八个 skill 的结构升级，以及六个候选新增题材。
- 非目标：不替换 Image2 图像模型；不将所有场景合并为一个超长 prompt；不改变原有的成年人、原创、非露骨安全边界。

## 架构

```text
用户请求
  └─ image2-portrait-director（意图识别、参数锁定、路由和模式分流）
       ├─ _shared/core（schema、冲突裁决、输出契约、安全与质量门）
       ├─ _shared/routes（通用视觉路线）
       ├─ _shared/tools（修复、参考图、一致性、文本降级）
       └─ 专题 skill（婚纱、球场、Lookbook、海报等）
```

### 总导演入口

新增 `image2-portrait-director`，用于开放式人像请求。它只加载一个主 Route，可叠加至多一个兼容气质 Overlay；当请求明显属于既有专题时，将用户引导或分流到对应 skill，而不复制专题内部规则。

总导演支持三种显式输出模式：

1. `提示词模式`：返回参数锁定、导演扩写、最终提示词和负面限制词。
2. `直接出图模式`：仅在用户明确要求时调用图像生成能力。
3. `参考图模式`：仅处理用户本人或拥有授权的成年人物/产品，先锁定受保护特征，再施加风格。

### 共享核心

新增或整理以下共享文档：

- `parameter-schema.md`：人物、服装、场景、动作、镜头、光线、画幅、用途、输出模式的统一字段及默认值。
- `route-registry.md`：路线触发词、互斥规则、兼容 Overlay 与目标 skill。
- `conflict-resolution.md`：用户显式参数优先；单次只能选一个主 Route；不安全或不可实现内容降级而非悄然替换。
- `output-contract.md`：默认完整输出与“只要最终提示词”的精简输出。
- `quality-gates.md`：年龄、构图、手部、服装、角色一致性、文字、风格漂移的检查清单。
- `reference-image-policy.md`：身份/产品保持、图像角色、可授权范围与失败降级。

## 通用视觉路线

首批共享路线：清透生活、都市时尚、法式慵懒、新中式、古风仙侠、复古港风、旅行度假、低调电影感、棚拍精修、电商服装展示、运动活力、超近景真实人像。

路线文件给出视觉决策和摄影约束，不作为可机械拼接的句库。最终 prompt 必须描述为一个可拍摄瞬间：时间片段、小事件、动作链、视线目标和少量环境细节。

## 新增专题优先级

第一批（高复用）：

1. `image2-ancient-costume-editorial`：古装、仙侠、新中式视觉，强调服装考据程度和幻想程度的可控选择。
2. `image2-travel-lifestyle-portrait`：城市/自然旅行、酒店度假与生活方式叙事。
3. `image2-ecommerce-fashion-catalog`：服装电商、模特展示、SKU 变体和商品一致性。
4. `image2-cinematic-story-portrait`：低调电影感、情节瞬间、连续光与可读阴影。

第二批（取决于用户需求）：

5. `image2-professional-headshot-branding`：职业头像、创始人形象、个人品牌。
6. `image2-motherhood-family-portrait`：成年家庭成员、亲子/家庭纪实；以温情和关系为重点，避开任何不当年龄化表达。

## 错误处理与降级

- 路由不确定：不猜测风格，使用中性通用路线并标注补充默认值。
- 风格冲突：保留用户明确需求，要求选择或以主 Route 统摄，不能混合两个主 Route。
- 文字不可靠：对海报、设定图提供无文字/留白可后期排版版本。
- 参考图不满足授权或年龄条件：改用原创成年人，不保留身份。
- 高风险表达：转译为成熟、原创、非露骨的编辑/商业语境，解释可保留部分。

## 验收标准

- 任意明确字段在参数锁定与最终 prompt 中均可追溯。
- 每次生成最多一个主 Route，且不覆盖用户安全的显式参数。
- 所有专题 skill 使用同一输出模式和负面约束结构。
- 参考图请求在生成前完成授权、角色和受保护特征检查。
- 海报、设定图、电商、婚纱与球场等现有专题各有至少一条端到端示例和回归用例。
- 新 skill 只新增本题材的差异化规则，公共逻辑必须位于 `_shared`。

## 实施顺序

1. 建立共享 schema、输出契约、质量门和路由注册表。
2. 建立总导演入口及首批通用 Routes。
3. 迁移并回归验证现有八个 skill，先处理 risk debugger、婚纱、Lookbook、球场。
4. 实现第一批四个新增专题及示例。
5. 根据真实调用频次决定第二批两个专题是否投入。
